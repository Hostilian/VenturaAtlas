Collaboration Room

Venture Atlas OS supports local browser-based workflows, realtime friend collaboration rooms, and full GitHub-native collaboration.

Create or join an interactive room to evaluate, vote, discuss, and shortlist venture ideas with friends in realtime.

Local / Private

Browser-based drafts, favorites, comparisons, and vote packets. Nothing leaves your device unless you choose.

  • Favorites saved in localStorage
  • Recently viewed ideas tracked locally
  • Comparison view for up to 4 ideas
  • Export vote packets as JSON
  • Download ideas as CSV or JSON
🐙

Git-Native

The canonical collaboration layer. Issues, PRs, evidence submissions, objections, and decisions — all versioned.

  • Open a GitHub Issue to report a factual error
  • Submit a PR to add a new idea or source
  • Use issue forms for structured objections
  • Pairwise vote packets committed as JSON
  • All decisions versioned in data/decisions.json
⚙️

Optional Backend

A backend adapter interface is defined but disabled by default. The static site is fully functional without it.

  • See collaboration/BACKEND_ADAPTER.md
  • Plug in any API that accepts the vote-packet schema
  • No hosted backend required for core features

Governance & Decision Process

Voting Rules

Rankings are determined by pairwise votes. Each participant submits a vote packet JSON, which is validated and committed. Consensus is calculated from all committed votes.

View Voting Rules

Decision Process

Formal decisions require evidence submissions and a documented objection window. Historical research-run winners are immutable snapshots and are not equivalent to a current group decision.

Decision Process

Evaluation Template

Each participant evaluates ideas against defined criteria: market size, founder fit, technical feasibility, evidence quality, and strategic alignment.

How to Contribute

  1. Fork the repository and create a branch for your changes.
  2. Add or update data in data/ideas.json following the schema in data/ideas.schema.json.
  3. Include provenance — every new claim must reference a source in data/sources.json.
  4. Run validation: npm test && npm run validate must pass.
  5. Open a pull request with a clear description of evidence and scope.
  6. Address review feedback — factual objections require source evidence to resolve.
